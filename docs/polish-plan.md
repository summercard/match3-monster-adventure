### 目标1: 游戏流程闭环
确保从启动到结算的完整流程顺畅无卡死：
- 启动 → 新手引导 → 主菜单
- 主菜单 → 各功能页面的入口和返回
- 关卡选择 → 战斗准备（队伍为空时自动引导编队）

- 战斗 → 结算（胜利/失败正确计算展示）

- 队伍编成 → 保存 → 回主菜单

## P4 - 性能优化（共 5 个子任务）

> P3 全部完成后执行。目标是确保所有美术效果在低端安卓微信小游戏环境下也能流畅运行（稳定 30fps+）。

### P4.1 shadowBlur 发光替换
- [ ] **P4.1.1** `sceneStart.js` 的 `_drawGlowButton` 移除 `shadowBlur`，改用预绘制的渐变圆/矩形图片或 `createRadialGradient` 模拟发光效果；检测低端设备自动降级为纯色描边

### P4.2 粒子系统优化
- [ ] **P4.2.1** `sceneStart.js` 的 25 个粒子 save/restore 改为 batch 绘制：统一设一次 globalAlpha，用 `beginPath` 一次绘制所有菱形；加入视口裁剪，超出屏幕的粒子跳过绘制

### P4.3 Canvas 缓存
- [ ] **P4.3.1** 为启动画面、主菜单等静态区域（标题、装饰线、版本号）创建离屏 Canvas 缓存，仅在 opacity 变化时重绘；场景切换后释放离屏 Canvas

### P4.4 渲染调用优化
- [ ] **P4.4.1** `renderer.js` 的 `fillText` 添加 font 缓存：同字号+同 weight 跳过重复设置 `ctx.font`；Toast 的十六进制颜色拼接改为 rgba() 格式避免 toString(16) 开销

### P4.5 动画系统性能保障
- [ ] **P4.5.1** `animation.js` 的 animations 数组添加上限（默认 100），超出时跳过低优先级动画；FloatingText/Toast/CaptureEffect 添加同屏实例上限（浮动文字 10、Toast 3、收服特效 2），超出时立即回收最早的实例

## 设计规范

### 色调系统
```javascript
const THEME = {
  primary: '#2979ff',
  primaryDark: '#1565c0',
  primaryLight: '#64b5f6',
  bgDark: '#0a0a1a',
  bgCard: '#16213e',
  bgPanel: '#1a1a2e',
  textPrimary: '#ffffff',
  textSecondary: '#aaaaaa',
  textMuted: '#666666',
  fire: '#ff6b35',
  water: '#4fc3f7',
  grass: '#66bb6a',
  thunder: '#ffd54f',
  light: '#e0e0e0',
  success: '#4caf50',
  warning: '#ff9800',
  danger: '#f44336',
  gold: '#ffd700',
  radiusSm: 6,
  radiusMd: 10,
  radiusLg: 16,
  margin: 16,
  gap: 8,
}
```

### 字体规范
```
标题：20-24px bold #ffffff
副标题：16px bold #ffffff
正文：14px normal #cccccc
辅助：11-12px normal #888888
数字/数值：16-18px bold（状态色）
```

### 按钮规范
```
主按钮：圆角矩形 10px，primary 色，白字 16px bold
  按下：primaryDark 色 + scale 0.95
次按钮：圆角矩形 8px，bgCard 色，白字 14px
危险按钮：圆角矩形 8px，danger 色，白字 14px
```

### 动画规范
```
淡入：opacity 0→1，300ms ease-out
滑入：translateX + opacity，200ms
按钮按下：scale 0.95，100ms
弹出：scale 0→1.1→1，300ms ease-out
飘字：translateY -30px + opacity 1→0，800ms
震动：translateX ±3px 循环，200ms
```

## 循环执行规则

1. **严格按 P0→P1→P2→P3 顺序，P0 没完成不做 P1**
2. **按子任务编号顺序执行**（P0.1.1 → P0.1.2 → ...）
3. **每次循环只做 1 个子任务**
4. **玩家视角验收**："如果我是第一次玩的玩家，这比之前好看/好用吗？"
5. **修改文件要少**（1-3 个），不要大范围重构
6. **完成后在 polish-plan.md 勾选 ☑**
