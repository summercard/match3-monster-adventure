## 架构设计

### 核心设计理念
1. **模块化**：每个系统独立，通过事件总线通信
2. **场景驱动**：游戏由多个场景组成，同一时间只有一个活跃场景
3. **数据驱动**：怪物、关卡等用JSON配置，逻辑与数据分离
4. **纯Canvas渲染**：微信小游戏环境，无DOM，纯Canvas绘制

### 游戏主循环
```
初始化 (game.js)
  → 创建 GameCanvas
  → 加载资源
  → 初始化事件总线
  → 进入主菜单场景

每帧更新 (requestAnimationFrame)
  → 处理输入
  → 更新当前场景
  → 渲染当前场景
```

### 事件系统
```
EventBus 支持的事件：
  - 'gem:swap'      宝石交换
  - 'gem:match'     宝石匹配
  - 'gem:clear'     宝石消除
  - 'battle:attack' 攻击事件
  - 'battle:damage' 伤害事件
  - 'battle:defeat' 击败怪物
  - 'capture:attempt' 尝试收服
  - 'capture:success' 收服成功
  - 'scene:change'  场景切换
```

### 三消核心算法
```
1. 用户交换两个相邻宝石
2. 检查是否有3连以上匹配
   - 无匹配 → 交换回来
   - 有匹配 → 进入消除流程
3. 消除匹配的宝石
4. 触发战斗伤害（根据消除的属性）
5. 重力下落填充空位
6. 检查新的匹配（连锁反应）
7. 重复3-6直到无新匹配
8. 检查敌方行动
9. 回合结束
```

## 技术要点

### Canvas适配
- 使用 `wx.getSystemInfoSync()` 获取屏幕尺寸
- 设计分辨率 750×1334（iPhone 6/7/8基准）
- 使用 `dpr` 缩放保证清晰度

### 触摸处理
- `wx.onTouchStart` / `wx.onTouchMove` / `wx.onTouchEnd`
- 滑动方向判断：计算起止点角度
- 防止快速多次操作（锁定状态）

### 性能优化
- 离屏Canvas缓存静态元素
- 对象池复用宝石实例
- 减少GC压力

### 数据存储
- `wx.setStorageSync` / `wx.getStorageSync`
- 存储玩家进度、队伍配置、怪物收集情况
- 后期可接入云开发
